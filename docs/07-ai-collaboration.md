# AI 协作叙事 —— 一个产品人如何用 AI 把想法做成软件

> 这份文档回答一个面试高频问题：**“你是怎么做这个项目的？”** 特别面向强调“AI 应用”的岗位（如毕马威 AI 应用产品实习生）。
>
> 核心叙事：作为**项目负责人 + 产品角色**，我借助 AI 工具（Claude Code / Cursor 等）把“家庭水质健康”的产品设想，从 0 做到两套可运行的软件著作权。**AI 是杠杆，产品判断和验收标准是我。**

---

## 1. 我的角色与 AI 的分工

| 环节 | 我做什么（产品判断） | AI 辅助什么（执行杠杆） |
|---|---|---|
| 需求定义 | 定“监测—分析—预警—处理”闭环、定“健康解读”差异化 | 辅助调研、整理竞品/文献 |
| 架构设计 | 定“数据源抽象”“前后端引擎同步”等关键决策 | 生成代码骨架、方案对比 |
| 交付落地 | 拆任务、写验收标准、判定“已实现 vs 规划中” | 批量实现 11 视图、REST/MQTT、测试用例 |
| 质量验收 | 定 24 项冒烟测试的标准、核对前后端阈值一致 | 自动生成测试、跑测试、定位失败 |

**一句话**：我负责“做什么、为什么、对不对”，AI 负责“快速做出来”。

---

## 2. 三个用 AI 协作的真实案例

### 案例 1：用“数据源抽象”解耦硬件与软件（架构决策）

- **问题**：硬件是最大不确定性（跨工科、周期长），若软件依赖硬件才能跑，产品交付会被卡死。
- **决策**：定义 `DataSource` 抽象接口，AI 帮我并行实现 Mock / HTTP / MQTT 三套实现，通过 `config.js` 的 `DATA_SOURCE_MODE` 一键切换。
- **结果**：硬件还没落地，软件就能完整演示、迭代；软著可独立登记。
- **AI 协作点**：我提架构约束（“必须能切换、接口统一”），AI 负责三套实现的一致性。

### 案例 2：前后端“同一领域模型”的同步维护（一致性）

- **问题**：三档阈值判定（safe/warn/danger）与“水质-健康”引擎在前端和后端各实现一次，改一处漏一处就会出 bug。
- **决策**：把阈值收敛到两份 `config.js` 的 `METRICS`，并写进项目规范（CLAUDE.md）让 AI 每次修改都**同时改两份**。
- **结果**：前后端判定一致，冒烟测试能跨层验证。
- **AI 协作点**：用“给 AI 的项目规范文档”固化一致性规则，AI 严格遵守，比人肉记忆可靠。

### 案例 3：24 项冒烟测试作为“AI 的验收标准”（质量）

- **问题**：AI 生成代码很快，但“看起来能跑”≠“逻辑正确”（阈值边界、MQTT 编解码、健康规则映射最易错）。
- **决策**：为核心逻辑定义可自动运行的冒烟测试，作为“完成”的硬标准。
- **结果**：前端 `node smoke_test.mjs` 24 通过 0 失败、后端 `npm run smoke` 通过，作为每次改动的回归门槛。
- **AI 协作点**：把“验收标准”写清楚给 AI，AI 才能写出对的测试并保证通过。

## 3. 我从中学到的“AI 协作方法论”（可迁移）

1. **先给约束，再让 AI 发挥**：明确架构边界（如数据源抽象）、一致性规则（前后端同步），AI 产出才可控。
2. **验收标准前置**：用可自动运行的测试定义“完成”，而不是看代码“像不像”。
3. **诚实区分“已实现”和“规划中”**：AI 很容易把申报书里的纸面承诺（如“机器学习”“ppb 精度”）当成已做成果，必须由**产品人**逐条核对、如实标注——这是我在这个项目里踩过并纠正的坑。
4. **图表/文档不能直接照搬**：AI 首版图表和初稿只是起点，要有“重画成统一风格、更有产品质感”的第二步。
5. **AI 有边界**：纯文本模型读不了图、会幻觉、上下文有限——知道边界才知道何时该换工具（如本项目的 JD 截图改用系统 OCR 读取）。

## 5. 边界声明（诚实）

- 本项目的**产品决策、架构设计、验收标准**由我（作为负责人）主导，AI 是执行杠杆，不夸大“AI 全自动完成”。
- 软件为**大创项目成果**，著作权归属河海大学，AI 工具为协作方式，不影响知识产权归属与诚实性。
