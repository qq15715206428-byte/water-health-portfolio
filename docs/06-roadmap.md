# 产品路线图 —— 家庭水质健康管理

> 从“验证产品价值”到“规模化 + 智能化”的三阶段路线。每个版本都对应明确的**卖点清单**与**里程碑**，便于对齐大创计划的三阶段技术路线，也便于向面试官讲清楚“下一步怎么走”。

---

## 1. 路线图总览（V1 → V3）

| 版本 | 主题 | 核心命题 | 状态 |
|---|---|---|---|
| **V1** | 从 0 到 1，验证“翻译层” | 把水质数据翻译成健康建议，能否让用户“看得懂、做得了” | ✅ 软件已交付（2 软著） |
| **V2** | 接入真实，闭合“闭环” | 接真实硬件 + 真实数据，跑通“监测→分析→预警→处理” | 🔜 规划中 |
| **V3** | 智能增强，规模化 | LLM+RAG 健康咨询 + 生态联动 + 商业化 | 🔜 规划中（科研路线 B 联动） |

---

## 2. 分版本详解

### V1（已完成）—— 验证产品价值

**目标**：用最小成本验证“健康解读”是否有价值，同时产出可软著登记的完整系统。

| 卖点 | 已实现能力 |
|---|---|
| 11 个功能模块 | 登录、仪表盘、实时监测、历史趋势、健康画像、健康方案、异常预警、设备管理、设备联动、健康报告、设置 |
| 核心引擎 | 三档阈值判定（safe/warn/danger）+ 健康画像→个性化方案 |
| 架构亮点 | 数据源抽象（Mock/HTTP/MQTT 可切换）、自绘 SVG 图表、本地缓存、PWA |
| 云平台 | MQTT Broker + REST API + 边缘计算 + AES 加密 |

**里程碑**：✅ 前端 24 项冒烟测试通过 / ✅ 后端核心逻辑测试通过 / ✅ 两项软著登记。

---

### V2（规划中）—— 接入真实，闭合闭环

**目标**：把 Mock 数据换成真实水质数据，验证“监测→分析→预警→处理”全链路。

| 卖点 | 关键动作 |
|---|---|
| 真实数据接入 | 接入公开水质数据集 / 实地采样，替换 MockDataSource |
| 硬件原型 | 双形态监测终端（便携款 + 旗舰家用款）设计 + 样机 |
| 闭环联动 | 真实设备联动（净水/软水/智能水龙头），验证“预警→自动处理” |
| 小规模试用 | demo 上线 + 5–10 名目标用户试用，跑通 V1 指标体系 |

**里程碑**：🔜 样机 2 台 / 🔜 demo 上线 + 试用复盘 / 🔜 一手问卷真实数据。

---

### V3（规划中）—— 智能增强，规模化

**目标**：用 AI 把“健康建议”从规则升级为“可信、个性化、可解释”，并探索商业化。

| 卖点 | 关键动作 |
|---|---|
| LLM 健康咨询（科研路线 B） | 用 LLM + 文献知识库（RAG）生成个性化、可溯源的健康建议 |
| 生态联动 | 接入智能家居生态，成为“水质健康”能力提供方 |
| 商业化 | 便携款（低门槛） + 旗舰家用款（全屋）双形态定价，订阅制健康报告 |

**里程碑**：🔜 LLM 健康建议 POC（`10-llm-poc/`）/ 🔜 论文 1–2 篇 / 🔜 知识产权 3–4 项。

---

## 3. 卖点清单（一句话版，可直接用于简历/面试）

1. **从“报数字”到“给方案”**：不是检测仪，是“水质 → 健康影响 → 可执行方案”的翻译与决策层。
2. **双形态 + 双引擎**：旗舰家用款（全屋）+ 便携款（多场景），三档阈值引擎 + 健康画像引擎。
3. **数据源解耦，硬件不卡壳**：Mock/HTTP/MQTT 三实现可切换，软件产品可独立交付迭代。
4. **本地优先 + 加密**：健康数据敏感，本地存储 + AES 加密是卖点也是合规底线。
5. **AI 增强路线**：规则引擎 → LLM+RAG 健康咨询，有清晰的技术演进与科研价值。

---

## 4. 风险与应对

| 风险 | 应对 |
|---|---|
| 硬件周期长、跨工科不确定 | 软件先行（数据源抽象），硬件用“选型 + 集成”而非自研传感器 |
| “健康解读”的专业可信度 | 引用权威文献 + 阈值对齐国标 + 后续 LLM 溯源（RAG） |
| 大厂品牌 App 入局 | 打“通用水质 + 便携场景 + 多品牌兼容”的差异化 |
| 健康数据合规 | 本地优先、脱敏埋点、AES 加密（`04-metrics.md` §3.1） |
