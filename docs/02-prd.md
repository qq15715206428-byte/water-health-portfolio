## 1. 产品概述与目标

### 1.1 背景
家庭饮用水与生活用水的水质问题（余氯、硬度、重金属、浊度等）长期「看不见、看不懂、不会处理」。现有产品要么过于专业（实验室设备），要么信息单薄（TDS 笔只显示一个数字），无法回答用户最关心的问题：**「这水对我和家人的健康有什么影响？我该怎么办？」**

### 1.2 产品目标
构建「监测—分析—预警—处理」闭环，让普通家庭：
1. **看得见**：随时查看水质数据（多指标、实时、历史）；
2. **看得懂**：把水质指标翻译成健康影响（皮肤/头发/身体）；
3. **做得了**：获得个性化用水方案，并联动净水/软水设备自动处理。

### 1.3 成功标准（对应数据指标）
见 `04-metrics.md`。核心为北极星指标「每周主动查看水质并采纳健康建议的活跃用户数」。

## 2. 用户与场景

### 2.1 用户画像（占位，待一手调研替换）
| 画像 | 特征 | 核心场景 |
|---|---|---|
| 家庭用户 | 有房、有净水器、关注老人/儿童健康 | 全屋水质总控、滤芯寿命管理 |
| 租房/宿舍 | 年轻、不确定水管状况 | 便携检测、免安装 |
| 母婴家庭 | 对余氯/重金属高度敏感 | 泡奶、洗澡用水安全 |
| 差旅人群 | 流动、不熟悉当地水质 | 便携、即时反馈 |

### 2.2 使用场景（示例）

**场景 A：出差旅行**
用户在酒店洗漱前，用便携监测器检测水龙头水质 → APP 显示余氯偏高、提示对敏感肌的影响 → 建议先用便携滤芯初步过滤 → 自动记录进健康报告。

**场景 B：家庭日常**
入户监测器 24h 监测全屋水质 → 某日硬度超标触发分级预警 → APP 推送「硬度偏高，建议启动软水设备」→ 用户一键联动软水机处理 → 处理后数据回落，预警解除。

## 3. 功能清单

### 3.1 移动应用（软著 1）—— 11 个功能模块

| # | 模块 | 功能说明 | 优先级 |
|---|---|---|---|
| 1 | 登录/注册 | 本地账号体系，账号数据存于本机浏览器 | P0 |
| 2 | 水质仪表盘 | 综合评分（红黄绿三色）+ 六项指标卡片（余氯/硬度/pH/浊度/温度等） | P0 |
| 3 | 实时监测 | 定时刷新，指标达标状态一目了然 | P0 |
| 4 | 历史趋势 | 日/周/月折线图，可切换指标 | P0 |
| 5 | 健康画像 | 皮肤/头皮/敏感点/家庭成员录入 | P0 |
| 6 | 健康方案 | 指标超标 + 画像 → 个性化饮水/护肤/护发建议 | P0 |
| 7 | 异常预警 | 分级预警（饮用水高风险/生活用水提示）+ 记录 | P0 |
| 8 | 设备管理 | 监测设备绑定/解绑/在线状态 | P1 |
| 9 | 设备联动 | 净水器/软水机/智能水龙头手动与自动联动 | P1 |
| 10 | 健康报告 | 周报/月报生成，复制/打印导出 | P1 |
| 11 | 系统设置 | 通知开关、数据清除、隐私说明、退出登录 | P1 |

### 3.2 物联网云平台（软著 2）—— 后端能力

| 能力 | 说明 |
|---|---|
| 设备接入 | MQTT 3.1.1 Broker（TCP 1883 + WebSocket），主题 `home/water/<metricKey>` |
| REST API | `GET /api/water/current`、`/history`、`/devices`、`/linkage`、`POST /linkage/:id/control` |
| 数据存储 | JSON 文件持久化 + 内存缓存（水质时序/设备/预警记录） |
| 边缘计算 | 三档阈值判定（safe/warn/danger），数据接入即时本地判定 |
| 健康分析 | 水质指标 + 用户健康画像 → 个性化用水建议（规则引擎） |
| 设备联动 | 净水器/软水机/智能水龙头/全屋净水系统的自动与手动控制 |
| 数据安全 | 口令哈希 + AES 数据加密 |

## 5. 核心业务规则

### 5.1 三档阈值判定（前后端一致，见 `CLAUDE.md`）
- 每项指标定义三档阈值：`safe`（安全）/ `warn`（提示）/ `danger`（高风险）。
- 判定结果驱动：仪表盘评分颜色、异常预警分级、联动控制触发。
- ⚠️ 修改阈值时需同步更新前端 `js/config.js` 与后端 `server/config.js` 的 `METRICS`。

### 5.2 健康画像 → 个性化方案
- 用户录入：皮肤类型（敏感/干/油/屏障受损）、头皮状况、身体敏感点、家庭成员构成。
- 规则：指标超标项 + 画像特征 → 匹配建议库 → 生成个性化饮水/护肤/护发方案。
- 示例：`余氯超标 + 敏感肌 → 建议"洗漱前放水 30s + 使用除氯花洒"`。

### 5.3 分级预警
- 区分「饮用水高风险」（立即停用提醒）与「生活用水提示」（建议性）。
- 预警方式：APP 弹窗 + 记录，异常状态实时推送。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 实时数据刷新延迟 < 3s；历史趋势图表渲染流畅 |
| 兼容性 | 移动端优先布局，主流浏览器可用（无需构建、零依赖） |
| 数据安全 | 口令哈希存储、水质/健康数据 AES 加密、本地优先存储 |
| 可扩展性 | 数据源抽象（Mock/HTTP/MQTT 可切换），便于接入真实硬件 |

## 7. 已知限制与后续规划

- 当前为 Mock 数据演示，需接入真实水质数据源；
- 健康分析为规则引擎，后续计划升级为 LLM + 文献知识库（RAG）的智能健康建议；
- 硬件终端（双形态监测器）为设计与选型阶段，尚未量产。
