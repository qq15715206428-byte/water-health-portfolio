# 打通水质监测「最后一米」：一个从 0 到 1 的家庭水质健康管理产品

> **一句话定位**：把「水质监测」从实验室和工业场景，下沉到普通家庭的每一次喝水、洗漱、洗澡——让用户**看得见水质、读得懂风险、做得了处理**，形成「监测—分析—预警—处理」的闭环。

> **一句话背景**：本项目由作者作为负责人发起的大学生创新创业训练计划（大创）项目，已产出两项软件著作权（移动应用 + 物联网云平台），本文是从产品经理视角的完整复盘。

## 1. 背景：为什么是「家庭水质」这个题

**市场侧：需求真实且仍在增长，但「最后一米」长期被忽视。**

- 中国净水器市场 2024 年零售额首破 **240 亿元**，同比增长 17.2%，销量 877 万台（奥维云网 AVC，2024）——但整体渗透率仅约 **23%**，对比美国 80%、日韩 90%+ 仍有巨大空间。
- 用户对水质安全愈发敏感：2025 年中国新国标《生活饮用水卫生标准》新增多项特征污染物指标；「68% 的美国房主 2025 年对自来水表示担忧」的类似情绪在国内同样存在。
- **但用户装了净水器之后，并不清楚水质到底好不好**——滤芯什么时候该换、出水是否真的达标，全靠「感觉」。

**产品侧：市面产品「要么专业到用不起，要么简单到没用」。**

- 实验室级水质分析仪：动辄数千元、体积大、需专业操作；
- 消费级 TDS 笔：只显示一个数字，**用户看不懂这个数字对自己意味着什么**；
- 净水器品牌 App：只服务自家设备，不解决「通用水质」问题。

**「检测」这件事，普通家庭其实从未真正拥有过。** 这就是「最后一米」——技术早已成熟，但没有一款产品把水质数据「翻译」成普通家庭能理解、能行动的信息。

## 2. 问题：用户到底痛在哪

通过场景拆解，我们把家庭用水的问题收敛为三个核心痛点：

| 痛点 | 用户原话（抽象） | 背后诉求 |
|---|---|---|
| **看不见** | 「水有没有余氯、干不干净，我完全不知道」 | 水质状态可感知 |
| **看不懂** | 「TDS 是 50 还是 500，对我皮肤有什么影响？」 | 数据 → 健康意义的翻译 |
| **不会处理** | 「知道水硬，但我该换净水器还是装软水机？」 | 从发现问题到可落地的解决方案 |

这三个痛点构成一条完整链路：**先要看得见，再要看得懂，最后要能处理。** 市面上没有任何单一产品同时覆盖这三个环节。

## 3. 用户：为谁做

**核心用户画像（四类场景，来自申报书调研 + 一手问卷占位数据）：**

| 用户群 | 典型场景 | 核心诉求 |
|---|---|---|
| 自住房家庭 | 全屋用水、母婴/老人同住 | 全屋水质总控、滤芯寿命管理 |
| 租房 / 宿舍人群 | 不确定水管是否老旧 | 便携、免安装、即装即用 |
| 母婴家庭 | 泡奶、宝宝洗澡 | 对余氯/重金属异常敏感 |
| 出差旅行人群 | 酒店、外地水质不确定 | 便携检测、即时反馈 |

> 📌 注：以上为**需求假设**，需用一手问卷/访谈验证（详见 `03-user-research.md`，当前为占位示例数据，待真实问卷替换）。

**核心用户故事（User Story）**：作为一位敏感肌用户，我希望在每次洗漱前知道今天自来水的余氯水平，以及它是否会影响我的皮肤屏障，并在超标时自动启动净水设备——这样我就不用「靠感觉」判断水质。

## 4. 方案：从「检测」到「健康闭环」的产品设计

### 4.1 产品架构（硬件 + 软件 + 云端三位一体）

```
┌──────────────────────────── 产品闭环 ────────────────────────────┐
│                                                                  │
│  监测终端(双形态)  →  物联网云平台  →  智能管理 APP  →  联动处理   │
│  · 入户总管式(旗舰)  · MQTT 接入    · 实时可视化    · 净水/软水   │
│  · 水龙头便携式(便携) · 数据汇聚存储  · 健康解读      · 智能联动   │
│                       · 阈值判定引擎  · 异常预警      · 自动控制   │
│                       · 健康分析引擎  · 个性化方案                │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

### 4.2 核心价值主张（三个差异化）

1. **看得见**：双形态监测终端覆盖「全屋 + 多场景」，水质数据 24 小时实时上传、手机随时查看。
2. **看得懂**：不做「报数机器」，而是把水质指标（余氯、硬度、pH、浊度等）**翻译成健康影响**——例如「余氯超标对敏感肌的刺激」「硬度过高对头发的损伤」，并给出**分级预警**（饮用水高风险 vs 生活用水提示）。
3. **做得了**：根据用户健康画像（皮肤类型、头皮状况、敏感点、家庭成员）生成**个性化用水方案**，并联动家用净水/软水设备**自动处理**，形成「监测—分析—预警—处理」闭环。

### 4.3 已实现的能力（软件侧，两套可运行系统）

**① 家庭水质健康智能管理移动应用（软著 1，纯前端 SPA）**

- 11 个功能模块：登录/注册、水质仪表盘（综合评分 + 六项指标）、实时监测、历史趋势（日/周/月折线）、健康画像、健康方案、异常预警（分级）、设备管理、设备联动、健康报告（周/月报）、系统设置。
- 核心引擎：**三档阈值判定引擎**（safe/warn/danger）+ **健康画像→个性化方案引擎**（规则映射）。
- 技术亮点：数据源抽象（Mock/HTTP/MQTT 三实现可切换）、自绘 SVG 图表（无第三方依赖）、本地缓存、PWA。

**② 家庭水质健康物联网云平台（软著 2，Node.js 服务端）**

- 设备接入：MQTT Broker（TCP + WebSocket），监测终端通过 `home/water/<metricKey>` 上报。
- REST API：实时/历史数据、设备、联动控制接口，供移动应用对接。
- 数据处理：三档阈值边缘计算 + 健康分析引擎 + 设备联动引擎 + AES 数据加密。

### 4.4 规划中（诚实说明：尚未兑现的部分）

- **硬件原型**：双形态监测终端（多参数传感器集成、水流自发电）——属于跨工科方向，当前为设计与选型阶段。
- **机器学习模型**：当前健康分析为**规则引擎（if-else + 阈值）**，尚未引入真实数据训练的 ML 模型；这是后续科研线（路线 B：LLM 健康咨询系统）要补的核心。
- **真实水质数据**：当前 demo 使用 Mock 数据源，需接入真实硬件或公开数据集验证。

> 说明：本文档如实区分「已实现」与「规划中」，避免把申报书的纸面承诺当作已完成成果。

## 7. 复盘：三个关键决策与下一步

**关键决策 1：把「健康解读」作为核心差异，而不是「检测精度」。**
市面上不缺少「更准的检测仪」，缺少的是「让用户理解并行动」的翻译层。我们把最有价值的工作放在「水质 → 健康影响 → 个性化方案」的映射上，而不是和硬件厂商拼参数。

**关键决策 2：用「数据源抽象」解耦硬件与软件。**
硬件是最大不确定性（跨工科、周期长），所以我们把软件层做成「Mock/HTTP/MQTT 三实现可切换」——即使硬件还没落地，软件产品也能完整演示、迭代。这让产品交付不被硬件卡脖子。

**关键决策 3：先用规则引擎验证产品逻辑，再用 ML/LLM 增强。**
MVP 阶段用 if-else 规则快速验证「健康解读」的产品价值；后续用 LLM + 文献知识库（RAG）升级为更智能、更可信的个性化健康建议——这也是一条有科研价值的技术路线（2025 年 LLM 健康咨询已有多项临床验证，如 EHR 集成的患者教育 Agent、多智能体 RAG 生活方式教练系统）。

**下一步（Roadmap V1 → V3 详见 `06-roadmap.md`）：**
1. 补真实用户调研数据（问卷 + 访谈）；
2. demo 上线 + 小规模试用复盘；
3. LLM 健康建议 POC（对接科研路线 B）。
