# 数据指标体系与埋点设计 —— 家庭水质健康管理

> 从“产品目标”反推“可衡量的指标”，再落到“需要埋哪些点”。目标是让产品决策有据可依，而不是凭感觉迭代。

---

## 1. 北极星指标（North Star Metric）

> **每周主动查看水质并采纳健康建议的活跃用户数（Weekly Active Adopters, WAA）**

**为什么是它**：它同时衡量了产品的两条核心价值——
- “看得见”（用户主动来看水质，而非被推送才看）；
- “用得上”（用户采纳了健康建议，说明“翻译层”真正产生了行动）。

如果只看 DAU，会误把“打开了 app”当作成功；WAA 把“打开”升级为“采纳”，更贴近产品使命。

---

## 2. 指标体系（北极星 + 过程指标）

### 2.1 指标分层

| 层级 | 指标 | 定义 | 说明 |
|---|---|---|---|
| **北极星** | WAA | 周内“主动查看 ≥1 次 且 采纳建议 ≥1 次”的去重用户数 | 核心健康度 |
| **激活** | 设备激活率 | 绑定设备用户 / 注册用户 | 硬件到软件的转化 |
| | 健康画像完成率 | 完成画像录入用户 / 激活用户 | “个性化”的前提 |
| **留存** | 7 日 / 30 日留存 | 第 7/30 天仍活跃用户占比 | 产品是否有持续价值 |
| **核心价值** | 健康方案采纳率 | 采纳建议次数 / 建议展示次数 | 翻译层有效性 |
| | 预警响应率 | 预警后触发联动/手动处理的比例 | 闭环是否闭合 |
| | 设备联动触发率 | 自动联动次数 / 需处理异常次数 | 自动化价值 |
| **质量** | 预警准确率 | 真异常 /（真异常 + 误报） | 信任基础 |
| **商业** | 付费转化率 | 订阅/硬件购买 / 活跃用户 | 商业可行性 |

### 2.2 指标关系（漏斗）

```
注册 → 激活设备 → 完成健康画像 → 首次采纳建议 → 周活跃采纳(WAA) → 付费
```

每一级都是前一级的子集，漏斗的“泄漏点”就是产品要优化的地方。

## 3. 埋点设计

### 3.1 埋点原则

- **事件驱动**：以“用户做了什么”为单位，而非“页面被打开”。
- **最小必要**：只埋能回答指标问题的点，避免数据噪音。
- **隐私优先**：健康数据本地优先，埋点只上传**行为**与**脱敏统计**，不上传原始健康画像/水质读数。

### 3.2 核心埋点事件表

| 事件名 | 触发时机 | 关键属性 | 对应指标 |
|---|---|---|---|
| `register` | 注册成功 | 渠道、设备类型 | 激活漏斗 |
| `device_bind` | 绑定监测设备 | 设备形态(入户/便携) | 设备激活率 |
| `profile_complete` | 完成健康画像 | 画像维度数 | 画像完成率 |
| `view_dashboard` | 打开仪表盘 | 主动/被动(推送) | WAA 的“主动查看” |
| `view_history` | 查看历史趋势 | 指标类型、时间范围 | 留存 |
| `advice_show` | 展示健康建议 | 建议类型、关联指标 | 采纳率分母 |
| `advice_adopt` | 采纳健康建议 | 建议类型 | **WAA 的“采纳”** |
| `alert_trigger` | 触发分级预警 | 等级、指标 | 预警质量 |
| `linkage_action` | 触发设备联动 | 手动/自动、设备 | 联动触发率 |
| `report_export` | 导出健康报告 | 周/月报 | 留存/分享 |

### 3.3 技术落地（与现有架构衔接）

- 前端 `js/storage/cache.js` 已有本地缓存封装（键前缀 `whh:`），可在其上增加**轻量行为埋点**：本地聚合 → 定时/触发时批量上报（Mock 阶段可只写本地日志）。
- 后端 `cloud-iot-platform` 的 REST API 可扩展 `POST /api/events` 接收脱敏事件；MQTT 链路仅传**水质读数**（非个人身份信息）。
- 数据清洗后接入简单统计（当前阶段用 Python/pandas 即可，见 `09-data-analysis/`）。

## 4. 指标如何驱动决策（示例）

| 场景 | 数据信号 | 产品动作 |
|---|---|---|
| 设备激活率高、但画像完成率低 | 用户在“录入画像”环节流失 | 简化画像流程 / 提供“跳过 + 默认画像” |
| 建议展示多、采纳率低 | 建议不够个性化或不落地 | 优化建议文案 / 增加“一键执行” |
| 预警触发多、联动率低 | 用户不信任自动处理 | 增加“先预览再执行”的确认机制 |
| 7 日留存低 | 单一“查看”缺乏复访钩子 | 增加周报推送 / 趋势变化提醒 |

## 5. 当前阶段说明（诚实边界）
